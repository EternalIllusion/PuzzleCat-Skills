# PuzzleCat 交互题安全性自查

> **免责声明**：本 skill 为社区整理，非平台官方文档；平台规则以平台当前公布为准，可能与平台内部实现存在差异。

以攻击者与网络安全专家的视角审视作者自己的谜题材料，找出玩家可能用来提前拿到答案、套取隐私或越权操作的路径，输出结构化的自查报告，帮助作者在上线前修掉这些风险。报告供作者本人使用，仅作自查参考。

## 收集材料

自查前确认用户已提供交互题题包的源码或压缩包，缺什么先向用户索要。

## 自查项（逐项执行）

### 1. 内容合规（重点，命中即严重风险）

对题面与题包内出现的文本，逐项检查以下维度：

- 政治敏感：涉及国家领导人负面、政治事件、敏感地域争议、颠覆国家政权等
- 色情/性暗示：裸露描写、性暗示语言、擦边内容、未成年人色情
- 暴力/血腥：极端暴力描写、血腥场景、虐待行为、自残引导
- 恐怖/惊悚：过度恐怖渲染、精神压迫、跳吓式内容
- 仇恨歧视：种族、性别、地域、残障、性取向歧视或仇恨言论
- 脏话/粗口：中文或任何语言的脏话、粗口、侮辱性词汇
- 外语隐蔽攻击：用韩语、日语、英语、小语种等写出的骂人话、侮辱性表达
- 隐私泄露：真实姓名、联系方式、地址等个人信息
- 引流广告：推广链接、商业广告、二维码引流

判定原则：**解谜包装（题材设定、虚构暴力等）默认不视为违规**，仅明确违规才标 🚨；边缘争议写入「需确认项」，勿硬打 🚨。属合规红线类内容（涉政、涉黄、“开盒”、引导网络暴力、极端血腥等）的明确标注，并提示作者先自行修改，必要时向平台确认规则。

命中时在报告正文之前逐行输出（引用位置、勿复述敏感原文）：

> 🚨 **[严重风险]** 风险类型：位置与类型描述

### 2. 安全性

以攻击者视角检查。**安全性问题不使用 🚨 标注**（🚨 仅留给合规红线），按「位置 + 类型 + 改法」写进「问题与修复建议」。

**A. 答案泄露**——把题面 HTML、图片/音频、交互包的全部源码与静态资源、文件与 URL 命名，都当作玩家已能拿到的材料，逐项与答案 JSON 比对。

- 明文答案：题面正文、图片/音频内容、富文本隐藏节点里是否直接出现主答案、别名或后续阶段答案。
- 交互包内残留：注释、变量名与常量、`data-*` 属性、CSS `content`、被注释掉的代码、`<details>` 等可展开节点、source map（`.map`）中是否含答案、题解或未解锁题面。
- 本地校验：包内做答案校验时是否落了明文。
- 提前可见：未解锁阶段的 `revealHtml`、未购买提示正文，是否被打进包内或被预先渲染进 DOM（建议哈希化存储或直接将阶段答案作为加密密钥）。
- 打包残留：ZIP 内是否混入源工程文件、导出的 `.psd` / `.ai` / 源 `.ts`、备份文件、测试用例、`.DS_Store`、`__MACOSX`、`node_modules`。
- 资源命名：文件名、`alt` 文本、图片 EXIF 等元数据（作者、软件、注释、GPS）是否直接或间接给出答案。
- 自查动作：F12 → Sources 里全量搜索答案与提示关键词；Network 看请求与响应；Elements 查隐藏 / 注释掉的节点；Application 看 `localStorage` / `sessionStorage`。

**B. 隐私与凭据**

- 个人信息：题面或题包内是否出现真实姓名、手机号、邮箱、住址、学校/单位、学号、未打码的聊天记录或带 GPS 的照片；引用的素材是否已获授权。
- 索取凭据：是否以任何形式要求玩家输入 PuzzleCat 账号密码、验证码、令牌，或索取其它平台账号信息；伪造「登录页」类交互一律标为高风险。
- 数据采集与外传：交互包是否读取玩家输入、剪贴板、摄像头、定位，或把任何数据发往第三方域名（含统计脚本、CDN、字体、图片打点）。
- 平台数据越界：是否读取平台登录态 / cookie，或绕过 SDK 直连平台后端接口。
- 外链与二维码：是否引导站外跳转、要求下载文件，或用二维码引流（该行为同时命中第 1 节的「引流广告」，按合规项处理）。

**C. 沙盒与外部依赖**

- 越权行为：包内是否访问 `parent` / `top`、改写父页面、`window.open` 弹窗，或用通配符 `postMessage` 通信。
- 外部依赖：是否从第三方 CDN 引入脚本、样式或字体——既有供应链风险，也可能在限制网络时加载失败；建议内联或随包提供。
- 危险 API：`eval` / `new Function`、把用户输入拼进 `innerHTML`（XSS 风险，且可能波及题面页）。

定级参考：命中「明文答案 / 索取凭据 / 向第三方外传数据」的属于必须先修复再上线的问题；仅有命名、打包残留之类轻微项的，在建议中给出具体替换或清理方案即可。

## 输出格式

- **自查结论**：未发现明显问题 / 存在需修复项 / 存在严重问题（任选其一；出现 🚨 行时选后两者）
- **主要理由**：简要说明（含内容合规与安全要点）
- **问题与修复建议**（如有）：指出具体位置与改法
- **需确认项**（如有）：图片、交互页、外链、边缘合规等
- **补充说明**（可选）

## 纪律

- 设计/可解性问题写进「问题与修复建议」，**不要标成合规 🚨**。
- 无合规风险则不输出任何 🚨 行。
- 报告末尾可附一段「上线前建议动作」（如替换表述、清理打包残留、内联外部依赖），但不得改变上述固定格式。

## 配套 skill

同一创作链路中还有两个 skill，如已一并安装，按需加载：

- `puzzlecat-content`——题面、答案 JSON、解锁规则 AST 的具体规范。
- `puzzlecat-interactive`——交互题包（沙盒 iframe）开发与打包规范。
